# 雷电构筑系统设计

## 目标

在已完成的 `DiceRevolverRuntime`、`DiceShotPipeline` 与 `DiceRevolverGun` 分层基础上，增加可持续扩展的五槽位骰面、弹幕类型与多标签、通用穿透、被动事件和雷电构筑。

本轮实现以下内容：

- 被动事件槽位与独立被动运行时。
- 弹幕类型 SO、弹幕标签 SO 及各自 Library。
- 通用弹丸穿透。
- 雷电球。
- 收尾者。
- 电磁共鸣与闪电链表现。
- 特斯拉。
- 呼应协同。
- 链式反应。

## 构筑原则

- 六发编排与连锁是核心骨架。
- 弹幕类型、标签和元素反应是主要内容层。
- 抽面控制、骰面返还、复制和风险收益属于稀有强化层。
- 基础事件负责发射内容；开火时事件负责发射方式；命中时事件负责命中结果；开火后事件负责后续枪膛；被动事件在装备期间持续监听条件。
- 单个词条保持简单，强度来自跨骰面、跨阶段和跨弹幕组合。
- 所有生成攻击的连锁继续受事件预算限制。

## 五槽位数据模型

每个骰面拥有以下互不占用的槽位：

1. 基础事件。
2. 开火时事件。
3. 命中时事件。
4. 开火后事件。
5. 被动事件。

`DiceFaceSlotType` 增加 `Passive`。`DiceFaceConfiguration` 与 `DiceFaceConfigurationSnapshot` 增加 `passiveEntry`，原四个序列化字段原位保留。

`DiceFaceEntry` 继续作为词条资源：

- 四个主动槽引用现有 `BulletEventEffect`。
- 被动槽引用新的 `PassiveEventEffect`。
- 主动与被动效果字段分离，避免用一次性 `Trigger` 模拟持续监听。

`PassiveEventEffect` 是无运行时状态的 SO 工厂。它为每个装备骰面创建独立运行时实例；层数、次数、耗尽状态和订阅只存在于实例中。同一种被动装备在多个骰面时，每个实例独立生效并允许叠加。

构筑页面为每个骰面显示第五行“被动”。运行时更换被动立即生效：旧实例注销，新实例以零状态创建；主动槽继续按下一次射击读取最新配置。已经固化的攻击快照和链式反应覆盖不被后续编辑改写。

## 弹幕类型与标签

新增：

- `ProjectileTypeDefinition`：稳定的弹幕类型身份。
- `ProjectileTypeLibrary`：保存所有弹幕类型。
- `ProjectileTagDefinition`：稳定的可组合标签身份。
- `ProjectileTagLibrary`：保存所有弹幕标签。

`ProjectileDefinition` 引用一个类型和多个标签。呼应协同比较类型 SO 引用；特斯拉、电磁共鸣等规则查询标签 SO。

“攻击特效”继续使用现有独立语义，不作为普通标签。旧字符串类型和标签保留为兼容迁移字段，迁移工具只补空引用，不改写伤害、速度、距离、穿透、Prefab 或用户资源调参。

基础类型资源至少包含基础左轮弹、雷电球、爆炸和闪电链。基础标签至少包含雷电和元素。

## 通用穿透

`Projectile` 正式执行已有的 `EnemyPierceCount`：

- `0` 表示命中第一个敌人后销毁。
- `N` 表示首次命中后还能穿透 `N` 个不同敌人，总命中上限为 `N + 1`。
- 同一受伤对象的多个 Collider 或重复接触只结算一次，也只消耗一次穿透。
- 命中敌人时广播命中、执行合格事件、提交直接伤害并扣除穿透次数。
- 命中不可受伤障碍物时立即销毁。
- 穿透耗尽、飞行距离耗尽或生命周期结束时销毁。

该行为属于通用弹丸模块，雷电球只通过定义配置穿透数。

## DicePassiveRuntime

新增普通 C# 深模块 `DicePassiveRuntime`，每把枪拥有一个实例。它管理六个被动运行时实例并接收明确领域通知：

- 换弹开始与完成。
- 构筑槽位变化。
- 抽面前候选过滤。
- 骰面正常开火与消耗。
- 弹幕生成。
- 合格弹丸命中。

被动只通过受限命令请求以下行为：

- 过滤抽面候选。
- 提供所属骰面的临时伤害修正。
- 请求额外骰面激活。
- 将所属骰面标记为本轮已消耗。

被动不能直接访问 Gun、Prefab、场景对象或 Runtime 内部集合。纯过滤和状态累计不消耗事件预算；生成攻击的请求必须消费因果攻击的共享预算。单个被动异常被记录并隔离，不中断其他被动、枪械或角色控制。

## 事件预算与触发顺序

一次正常左键射击创建一个事件预算对象。由该射击产生的延迟、命中、被动额外激活和子攻击共享该对象，不为子激活重新补满预算。

顺序固定为：

1. 换弹完成时重置本轮被动状态。
2. 抽面前由被动过滤候选。
3. Runtime 抽取真实骰面。
4. Pipeline 取得配置并应用一次性链式反应覆盖。
5. 基础弹幕生成时读取已有伤害修正。
6. 弹幕登记完成后通知特斯拉等被动累计状态，因此弹幕不享受自己新增的层数。
7. 弹丸命中时先执行其所属攻击链的命中时事件，再通知呼应协同。
8. 正常射击完成后通知骰面消耗；所属骰面被正常射击会停止其呼应协同。
9. 换弹开始时清除本轮被动状态、未使用覆盖和待执行连锁。

## 收尾者

收尾者是被动事件，不占主动槽：

- 只要还有普通骰面，装备收尾者的骰面不进入随机池。
- 普通骰面耗尽后，所有剩余收尾者进入随机池。
- 多个收尾者占据最后几发，并在彼此之间随机抽取。
- 收尾者优先级高于强制抽面。
- 若强制目标是当前不可抽取的收尾者，强制请求保留，直到目标进入可抽取阶段。
- 若过滤出现无候选异常，回退到真实剩余骰面，避免枪膛卡死，并记录警告。

## 雷电球

雷电球是普通 ProjectileDefinition 与 Prefab，不在 Gun 中写死行为。

默认参数：

- 类型：雷电球。
- 标签：雷电、元素。
- 伤害：`1`。
- 飞行速度：`5`。
- 飞行距离：`15`。
- 敌人穿透数量：`4`，总计最多命中五个不同敌人。
- 默认攻击特效：关闭。
- 碰撞半径：`0.35`。

命中后按通用穿透规则继续飞行。所有数值使用中文 Inspector 端口开放。

## OwnedProjectileRegistry

每把 Gun 拥有独立 `OwnedProjectileRegistry`：

- Gun 生成弹幕后登记。
- Registry 保存该枪仍存活的弹丸句柄。
- 可按类型、标签、距离和存活状态查询。
- 弹丸销毁时注销；查询也会清理失效引用。
- 玩家与敌方 Gun 的 Registry 天然隔离，不引入全局静态列表或完整阵营系统。

弹丸生成适配器返回运行时句柄。`DiceFaceActivation` 记录本次主弹句柄，使紧随基础事件执行的开火时事件能够定位新雷电球。

## 电磁共鸣

电磁共鸣是开火时事件，只在本次主弹带有雷电标签时执行：

1. 以新雷电球为起点查询同一 Registry。
2. 在搜索半径内随机选择不重复的其他雷电弹幕。
3. 按选择顺序组成新球到其他球的链路。
4. 雷电球参与共鸣后继续存活。

默认参数：

- 搜索半径：`6`。
- 最大连接数量：`3`。
- 闪电链伤害：`1`。
- 伤害检测宽度：`0.25`。
- 视觉持续时间：`0.2` 秒。

所有参数开放中文 Inspector 端口。没有可连接雷电球时正常结束，不报错。

## LightningChainExecutor

闪电执行器与电磁共鸣选择逻辑分离：

- 接收按顺序排列的雷电球节点和闪电定义。
- 为相邻节点生成 LineRenderer 闪电表现。
- 沿每段线检测受伤对象，整次共鸣统一按 `IDamageReceiver` 去重。
- 同一敌人在一次共鸣中最多受到一次伤害。
- 发射者免疫自身闪电。
- 节点提前销毁时跳过对应段，不影响其他段。
- 视觉结束后自行销毁。

闪电链不是攻击特效，不广播弹丸命中，不触发命中时事件，也不触发呼应协同。闪电链类型与雷电球类型不同。

## 特斯拉

特斯拉是被动事件：

- 每个实例只强化所属骰面的基础弹幕。
- 每生成一颗带雷电标签的实际弹幕，该实例增加一层。
- 加法倍率为 `1 + 层数 × 5%`。
- 弹幕先读取旧层数，再通知特斯拉增加新层，因此不享受自己的新增层数。
- DoubleTap、呼应协同等生成的同一基础弹幕可获得所属骰面的倍率。
- 爆炸、闪电链和其他类型攻击不获得该倍率。
- 手动或自动换弹开始时层数清零。
- 修改的是生成时的 `ProjectileRuntimeStats`，绝不改写 ProjectileDefinition。

每层百分比通过中文 Inspector 端口开放，默认 `5%`。

## 呼应协同

呼应协同是被动事件：

- 装备时读取所属骰面基础弹幕的类型。
- 任意同一 Gun 的相同弹幕类型命中敌人时，立即额外激活所属骰面。
- 每个实例每轮最多触发 `4` 次。
- 同一帧允许多次触发，不增加时间延迟。
- 额外激活不消耗普通射击冷却或其他真实骰面。
- 所属骰面被正常抽中并完成射击后立即消耗并停止呼应；未发生的后续触发失效。
- 换弹后恢复四次额度。
- 额外激活临时移除呼应协同自身，避免直接递归，并共享因果攻击预算。

每次协同射击从当前枪口姿态生成，并加入自然散布：

- 默认最大散布角：`8` 度。
- 默认同帧最小角度间隔：`2` 度。
- 同帧已使用角度过近时重新取样。
- 随机源通过接口注入，保证测试可复现。

## 链式反应

链式反应是开火后事件。它创建一次性的下一发主动槽覆盖层，不修改 Loadout 或 SO：

1. 当前骰面完成主动事件。
2. 链式反应先从来源运行时快照中移除自身。
3. 保存来源四个主动槽中的剩余非空槽。
4. 下一次正常射击仍由 Runtime 抽取并消耗真实骰面。
5. 以目标骰面的原始四槽为基础，使用来源非空槽覆盖对应槽。
6. 来源空槽保留目标原值。
7. 被动槽永远不参与覆盖。
8. 覆盖使用一次后销毁；换弹清除未使用覆盖。

链式反应自身被移除后，目标骰面的开火后槽不会被它擦除，因而可以保留 LoadedFour 或另一项开火后事件。

多个覆盖在下一次正常射击前产生时按触发顺序合并：后触发的非空槽覆盖先前对应槽，空槽永远不擦除已有内容。

该状态由 `DiceShotPipeline` 管理；`DiceRevolverRuntime` 不认识事件配置。

## 资源与构筑页面

创建并加入 Library：

- 雷电球基础事件。
- 收尾者被动。
- 电磁共鸣开火时事件。
- 特斯拉被动。
- 呼应协同被动。
- 链式反应开火后事件。
- 类型与标签资源及各自 Library。

新内容只进入 Library，不自动装备到 Player 或 TestRobot。不得修改现有六面基础左轮弹、DoubleTap、BlastRound、LoadedFour、枪械调参、AimRoot、Sorting Layer 或用户 Transform。

资源通过定向、幂等的 Editor Builder 创建：只创建缺失资源、只补空引用，现有资源和用户调参不得被覆盖。不得运行完整场景或 Player 重建 Builder。

## 错误处理

- 缺少类型或标签引用时记录具名警告并安全跳过对应组合判断。
- 单个被动创建或通知异常被隔离，其他被动继续执行。
- Registry 中失效弹丸自动清理。
- 闪电节点失效只跳过对应段。
- 没有可连接雷电球时电磁共鸣无操作结束。
- 没有抽面候选时使用剩余骰面回退。
- 事件预算耗尽继续使用现有单次警告规则。
- 缺少 Prefab 或定义时沿用 Gun 的安全跳过规则。

## 实施阶段

1. 五槽位、类型/标签 SO、Library 与兼容迁移。
2. 通用穿透及同一受伤对象去重。
3. `DicePassiveRuntime`、被动工厂与收尾者。
4. 雷电球与 `OwnedProjectileRegistry`。
5. 特斯拉和生成时伤害修正。
6. 电磁共鸣与 `LightningChainExecutor`。
7. 呼应协同与同帧散布。
8. 链式反应覆盖合并。
9. 构筑 UI、资源接线、完整回归和可见 PlayMode 验收。

每阶段执行测试先行的红绿循环，不同时修改无关模块。

## 测试策略

### 数据与迁移

- 五个槽位互不占用并生成不可变快照。
- 旧四槽位资源与 Prefab 正常读取。
- 类型和多标签按 SO 身份比较。
- 定向 Builder 重复执行不覆盖现有参数。
- 构筑页面显示、装备和刷新第五槽。

### Runtime 与 Pipeline

- 收尾者过滤、多收尾者顺序、强制抽面等待和无候选回退。
- 链式反应非空覆盖、空槽保留、被动排除、多覆盖顺序和换弹清理。
- 子激活共享事件预算且异常隔离。
- 被动中途替换只重置所属实例。

### Projectile 与雷电

- 穿透总命中数、同接收者去重、障碍销毁和命中事件次数。
- Registry 所有者隔离、标签查询、范围查询和销毁清理。
- 雷电球默认定义与中文端口。
- 电磁共鸣随机不重复连接、范围、节点失效和伤害去重。
- 闪电链不触发命中时事件或呼应协同。

### 被动效果

- 相同被动多面独立叠加。
- 特斯拉先结算旧层数再加层、换弹清零和定义资源不变。
- 呼应协同同类型匹配、四次上限、正常射击停止、同帧散布和共享预算。
- 收尾者、特斯拉和呼应协同异常不影响正常射击。

### 回归与保护

- 运行受影响聚焦 EditMode 测试。
- 运行完整 EditMode；已知 Ground `Y=-0.01` 豁免失败必须保持唯一且身份不变，不得新增失败。
- 核对 Player、TargetDummy、TestRobot Prefab 及玩家枪械关键参数。
- 运行项目上下文检查和 `git diff --check`。
- 可见 PlayMode 人工验收六发、换弹、雷电球穿透、共鸣闪电、特斯拉成长、呼应散布与链式覆盖。

## 非目标

- 不实现完整阵营、状态异常、元素反应、对象池或存档。
- 不自动为 Player 或 TestRobot 装备新词条。
- 不重做角色控制、AI、伤害数字、爆炸、摄像机、场景或美术层级。
- 不把闪电链标记为攻击特效。
- 不允许链式反应复制被动。
